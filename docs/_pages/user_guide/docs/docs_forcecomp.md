# Force Computation (F, T)

## Computation Idea

Force and torque computation in Magpylib stands in contrast to the analytical models used for magnetic field computation. They are based on a numerical approach that solves the force integrals over the target objects by discretization, see also [Physics and Computation](guide-physics-force-computation).

-------------------------------------
## Force Interface

:::{versionchanged} 6.0
`meshing` is an argument of `getFT()`, no longer of the targets, and the torque on a `Collection` target is taken about the Collection's centroid.
:::

Force and torque are computed in the [object-oriented interface](docs-fieldcomp-oo) via the top level function **`getFT()`**

```python
F, T = magpylib.getFT(
    sources,
    targets,
    pivot="centroid",
    eps=1e-5,
    squeeze=True,
    meshreport=False,
    return_mesh=False,
    *,
    meshing=None,
)
```

where F is the force in units (N) and T is the torque in units (N*m) acting on the `targets` via the magnetic field generated by the `sources`. F and T are NumPy arrays of shape (s, p, t, 3), where s is the number of sources, p is the path length, and t is the number of targets. Sources and targets may carry a path in any of their `path_properties`: a motion, a current ramp or a growing magnet alike (see {ref}`docs-position-path-properties`). p is the longest of these paths; shorter ones are edge-padded.

- **`sources`**: single or 1D list of magnetic field generators
- **`targets`**: single or 1D list of targets (all Magpylib currents, magnets, and `Dipole`). A `Collection` counts as one target and gets the force and torque on it as one body.
- **`meshing`**: how finely each target is cut for the computation. An integer applies to every target, a dict keyed by target gives one value per target, `meshing={ring: 100, coil: 40}`, and a `Collection` key covers its members. Required for every target except `Dipole` and `Sphere`, see [Meshing](docs-forcecomp-meshing) below.
- **`pivot`**: The torque is always defined relative to a pivot point $\vec{r}_\text{piv}$, and the force adds to it via $\vec{T}_F = \vec{F} \times (\vec{r}_\text{piv} - \vec{r}_\text{pos})$. For a freely floating magnet this would be the barycenter (= centroid when the density is homogeneous). If `pivot='centroid'` each target's centroid is the pivot point, for a `Collection` target the centroid of the Collection. If `pivot=None` no pivot is used. This will give nonphysical results. If `pivot` is array-like of shape (3,) the same pivot is used for all targets. Alternatively one can provide an individual pivot point for each target.
- **`eps`**: finite difference step size for computation of the magnetic field gradient (only needed for magnet targets). A good number is 1e-6 * characteristic source size.
- **`meshreport`**: Set to `True` for printing the number of mesh points of each target giving you an idea of the involved computation effort.
- **`return_mesh`**: Set to `True` for returning the mesh instead of F and T. In this case, a list of mesh dictionaries will be returned which have keys `"pts"`, `"moments"` (only magnets), and `"cvecs"` (only currents).

```{warning}
F and T are computed in SI units (N) for F and (N*m) T. Note that [scaling invariance](guide-docs-io-scale-invariance) does not hold for force computations! Be careful to provide the correct input units!
```

The following minimal example computes the force acting on a current loop, generated by a cuboid magnet.

```python
import numpy as np
import magpylib as magpy

cube = magpy.magnet.Cuboid(dimension=(1, 1, 1), polarization=(0.1, 0.2, 0.3))
loop = magpy.current.Circle(
    diameter=2,
    current=1e3,
    position=(0, 0, 1),
)
F, T = magpy.getFT(cube, loop, meshing=40)

print(f"force: {np.round(F, decimals=2)} N")
# force: [ 13.67  27.33 -82.  ] N

print(f"torque: {np.round(T, decimals=2)} N*m")
# torque: [-8.54  4.27  0.  ] N*m
```

## Meshing

:::{versionchanged} 6.0
Cylinders are cut into near-cubic cells and tetrahedra into equal ones, so their forces change at the same `meshing`.
:::

The `meshing` argument of `getFT()` is a positive integer: the target number of cells the target is cut into. One integer applies to every target; a dict keyed by target, `meshing={ring: 100, coil: 40, cube: (10, 10, 10)}`, gives each its own. Magnets are cut into cells of their own kind, and the force acts at the cell centroids with the cell volumes. Currents are cut into line or surface elements. The algorithms aim for uniform cells with aspect ratio close to 1, so the cell count is close to, but not always exactly, `meshing`. A bool is not a valid `meshing`, NumPy integers are.

| Class | `meshing` | Cells |
|---|---|---|
| `Cuboid` | target number of cells, or `(n1, n2, n3)` divisions along the sides | cuboids, as close to cubes as possible |
| `Cylinder`, `CylinderSegment` | target number of cells, or `(nphi, nr, nh)` divisions along the arc, the radius and the height | cylinder segments as close to cubes as possible, as for `Cuboid`: rings cut along the angle in proportion to their middle radius, thin rings with enough cuts to keep each cell's centroid inside them; the innermost ring of a full cylinder with at least 3 rings stays a cylinder |
| `Tetrahedron` | target number of cells, rounded to the closest cube number m³ | m³ tetrahedra of equal volume |
| `TriangularMesh` | target number of cells | cubes on a regular grid inside the surface |
| `Sphere`, `Dipole` | not needed | one point, exact |
| `Circle` | number of segments, at least 4 | straight segments of a polygon with the circle's area |
| `Polyline` | number of mesh points, at least the number of line segments; fewer warns and uses one per segment | straight segments, one point each, the rest distributed by length |
| `TriangleStrip`, `TriangleSheet` | number of triangles, at least the number of faces | triangles, the largest cut along its longest edge |
